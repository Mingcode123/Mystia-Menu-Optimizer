# 数据来源与运行工作簿

## 发布快照

根目录 [东方夜雀食堂.xlsx](../东方夜雀食堂.xlsx) 是由作者原工作簿制作的运行数据快照，不是完整原件。它保留原程序需要的七张表及其原顺序：

```text
稀客、普客、料理、食材、酒水、食材merchant_data、酒水merchant_data
```

原工作簿另有五张图像映射表和一张笔记表，它们不属于发布快照。制作时读取 Excel 已保存的缓存值，不复制公式或内嵌图片；Icon 列清空，私人路径和元数据不随包发布。网页图片由原独立资源目录提供。

快照**不修正采购价、不替换供给值、不重算期望、不改写 Owned**。各原脚本继续按自己的规则处理相同输入值。快照来源、原件与发行文件 SHA-256、逐表规模和处理记录见 [workbook-provenance.json](../data/workbook-provenance.json)。

在 Icon 清空这一约定下，七表 4,422 个单元格已与原缓存值逐项核对。原 `nCookware` 四个解析器读取原件与快照，得到相同的 62 条食材记录、164 道料理记录（其中 163 道持有）、58 位稀客及 62 条供给记录。这是该入口的解析对照，不代表其他脚本的全部展示字段都未经变化；例如旧类对象读取的 Icon 缓存已清空。详细验证范围见[验证记录](verification.md)。

## 价格期望与日供给

历史价格整理采用过数量加权口径：渠道单位价为 $`p_i`$、对应数量为 $`q_i`$ 时，估计单位采购价为：

```math
\bar p=\frac{\sum_i p_iq_i}{\sum_i q_i}
```

这一表达要求总数量非零，且分子、分母采用相同来源口径。委托数量若进入分母但没有相应现金支出项，就相当于在该口径中按零采购现金处理，仍没有计算时间和机会成本。它是历史数据处理假设，不是完整经济成本。

部分历史食材采购价按行号引用商贩表，而两表排序不同，存在关联错位风险。当前快照保留原缓存值，不把这些值静默替换成按名称修正的结果。独立利润报表因此应结合数据口径审阅；PLAN 的主要比较量仍是喜好覆盖、食材件数和供给余量，不能将件数解释为采购金额。

`Total Daily Quantity` 是日供给经验记录，不是玩家当前库存，也不是每天必定获得的数量。逐客余量用 $`q_i-Kc_i`$ 表达假设需求后的压力，允许负值，不包含其他顾客的联合消耗。

## 工作簿输入结构

<a id="workbook-schema"></a>

网页及 PLAN 系列主要使用以下四表。其他菜单和利润脚本还使用普客、酒水及酒水供给资料。

| 表名 | 常见原字段 |
| --- | --- |
| `食材` | `Name`、`Tags`、`Buy Price`、`Level` |
| `料理` | `Name`、`Tags`、`Cookware`、`Sell Price`、`Required Ingredients`、`Forbidden Ingredients`、`Owned` |
| `稀客` | `Name`、`Type`、`Preferred Tags`、`Disliked Tags`、`Budget` |
| `食材merchant_data` | `Name`、`Total Daily Quantity`、`Average Buy Price` |

这些是原字段示例，不是新增的严格校验协议。原网页、PLAN 解析器与类菜单对别名、空行、默认值和类型的处理各不相同。`nCookware` 支持稀客空姓名续行；网页按原 Type 条件筛选。自有文件应以根快照和选定脚本为参照，不使用结果工作簿作为源数据。

追加或基础用量中的重复食材仍以重复名称表示。需要修改自有公式时，应先在电子表格软件中重算并保存缓存；原程序不承担 Excel 公式计算。发布快照自身为值容器，不能从它恢复原公式和采样过程。

原完整工作簿、历史利润表、带图规划表、原始聊天、完整游戏资料与备份留在本地。公开审计是制作记录，不是新的规划输入或自动修复器。原始文件、运行快照与输出的关系见[输入输出说明](input-output.md)。
