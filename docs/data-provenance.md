# 数据来源与输入定义

## 数据组成

根目录 [东方夜雀食堂.xlsx](../东方夜雀食堂.xlsx) 为作者整理的历史游戏数据工作簿，发布文件与原件逐字节一致。工作簿共 13 张表，其中七张为业务数据表：

```text
稀客、普客、料理、食材、酒水、食材merchant_data、酒水merchant_data
```

其余工作表包括五张图像映射表和 `Sheet1`。完整文件包含公式、已保存的计算结果、格式、图片、Icon 字段及文件元数据。网页图像由独立资源目录提供。

`nCookware` 解析得到 62 条食材记录、164 道料理记录（其中 163 道标记为持有）、58 位稀客及 62 条供给记录。发布过程采用整文件复制，采购价、供给、期望值与 `Owned` 均沿用历史记录。文件 SHA-256、工作表规模及复制方式见 [workbook-provenance.json](../data/workbook-provenance.json)；运行验证范围见[验证记录](verification.md)。

## 字段来源

| 内容 | 来源与限制 |
| --- | --- |
| 标签和顾客偏好 | 作者确认历史标签资料来自 [AnYiEE 的东方夜雀食堂小助手](https://github.com/AnYiEE/touhou-mystia-izakaya-assistant)；当年实际导入的精确提交未完整留存 |
| 价格、日供给、委托相关记录 | 作者在游戏中手工记录和整理，并计算经验期望；完整观测次数、日期和采样过程未留存 |
| 配方和其他字段 | 沿用历史工作簿，逐字段的完整来源链未保存 |
| 派生价格和分析结果 | 由历史公式及其已保存结果构成，包含当时的数据处理假设 |
| 网页头像与料理图标 | 作者保留的图标包，与上游整理的游戏 sprite 对照；只用于显示 |

现有记录缺少完整的版本覆盖、采样日期和观测次数信息，因此价格与供给用于描述历史经验条件。标签资料、软件组件和游戏美术的来源分别记录于[第三方声明](../THIRD_PARTY_NOTICES.md)。

## 价格期望与日供给

历史工作簿采用数量加权口径估计单位采购价。对食材 $`i`$，设 $`\mathcal O_i`$ 为纳入计算的渠道记录集合，$`\pi_{i\ell}`$ 为记录 $`\ell`$ 的单位价，$`w_{i\ell}`$ 为对应数量，则：

```math
\bar\pi_i=\frac{\sum_{\ell\in\mathcal O_i}w_{i\ell}\pi_{i\ell}}
{\sum_{\ell\in\mathcal O_i}w_{i\ell}},\qquad
\sum_{\ell\in\mathcal O_i}w_{i\ell}>0
```

单位价及加权均价以游戏货币／件计，渠道数量以件计；价格与数量须对应相同的来源范围。若委托数量计入分母而无对应现金支出项，其采购现金成本在该口径下视为零。时间成本与机会成本未纳入估计。

部分食材采购价公式按行号引用商贩表，两表排序差异可能导致关联错位；工作簿同时存在部分公式错误缓存。这些历史状态均保留在发布文件中，构成价格分析的已知数据局限。PLAN 系列比较喜好覆盖、食材件数和最低供给余量，其中食材用量按件计量，每份用料与预计日用料分别统计，独立于采购金额。

`Total Daily Quantity` 对应估计日供给 $`q_i`$（件／日）。设每客日订单量为 $`K`$（单／日），单份方案使用食材 $`i`$ 的数量为 $`c_i(p)`$（件／份），则 $`q_i-Kc_i(p)`$ 表示该顾客需求下的供给余量（件／日）。该量允许为负；模型按顾客独立核算，未合并其他顾客的消耗。日供给估计与玩家即时库存具有不同含义。

## 工作簿输入结构

<a id="workbook-schema"></a>

网页及 PLAN 系列主要使用以下四表。其他菜单和利润脚本还使用 `普客`、`酒水`。`酒水merchant_data` 保留为工作簿公式的数据来源；现有脚本未直接将其供给字段用于规划或利润计算，但相关公式的已保存结果可影响读入值。

| 表名 | 主要字段 |
| --- | --- |
| `食材` | `Name`、`Tags`、`Buy Price`、`Level` |
| `料理` | `Name`、`Tags`、`Cookware`、`Sell Price`、`Required Ingredients`、`Forbidden Ingredients`、`Owned` |
| `稀客` | `Name`、`Type`、`Preferred Tags`、`Disliked Tags`、`Budget` |
| `食材merchant_data` | `Name`、`Total Daily Quantity`、`Average Buy Price` |

各入口分别实现字段别名、空行、默认值和类型处理。`nCookware` 支持稀客空姓名续行；网页依据 `Type` 字段筛选稀客。自定义输入应保持所选入口需要的工作表与字段结构。候选表和规划输出的结构不同于源工作簿，具体接口见[输入输出说明](input-output.md)。

重复食材用量以重复名称表示。程序读取工作簿已保存的单元格结果，公式重算由电子表格软件完成。修改公式或其输入后，需在支持相应公式的电子表格软件中重算并保存，再启动查询或规划。公式及缓存值共同构成输入文件的复现条件。

## 图像资源与分发范围

[HTML/icon_map.js](../HTML/icon_map.js) 将名称映射至 [HTML/izakaya_icons_pack/](../HTML/izakaya_icons_pack/) 下的 58 张稀客头像和 163 张料理图片。图像用于界面识别，供给与评分计算使用工作簿数值。`nCookware` 输出中的 `Name Icon`、`Dish Icon` 列为空占位。

仓库分发完整工作簿及网页使用的图像资源。独立历史利润表、带图规划表、原始聊天和完整游戏资料未纳入分发范围。数据审计文件用于记录来源与文件一致性；程序输入仍为 XLSX 工作簿。
