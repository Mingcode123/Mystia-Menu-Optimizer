# 验证方法与结果

验证分为文件一致性检查、优化前后差分对照和完整工作簿运行。优化前基准保存在 [v1.0.0 Release](https://github.com/Mingcode123/Mystia-Menu-Optimizer/releases/tag/v1.0.0)。本页区分当前实现的差分结果与该基准版的既有运行记录。

基准源码可通过 [v1.0.0 标签](https://github.com/Mingcode123/Mystia-Menu-Optimizer/tree/v1.0.0) 浏览，完整项目可在对应 Release 下载。本页“当前实现”的程序和资源数量统计仓库根目录的 `Python/`、`index.html` 与 `HTML/`。

## 当前实现的修改边界

| 范围 | 当前状态 | 核对方式 |
| --- | --- | --- |
| 四个 `singlePLAN_cover3*` 脚本 | 增加封顶效用下的食材件数搜索界限 | 对照候选对象、方案选择、命令行及输出工作簿 |
| 其余七份 Python 文件 | 保留 v1.0.0 内容 | 逐文件 SHA-256 |
| `index.html` | 标签计算与搜索缓存优化、停止机制修复、像素风格样式 | 对照 Worker 输出、主线程筛选、原 DOM 文本和浏览器操作 |
| SheetJS、图标映射及 221 张 PNG | 保留 v1.0.0 内容 | 223 个资源文件逐字节比较 |
| 完整输入工作簿 | 保留原件全部内容 | XLSX 字节及 SHA-256 比较，不重新保存 |

计算等价的比较对象包括完成计算后的候选值、顺序、选择结果和导出结构。界面样式与停止响应单独验证；停止时直接终止 Worker，丢弃未完成任务。

## 当前 Python 差分验证

`nCookware` 使用相同完整工作簿、最低分 3、每客日订单量 5、无流行喜爱和流行厌恶「水产」，对照 v1.0.0 与当前实现。58 位顾客的每厨具最优候选按字段逐项比较，结果一致；共同厨具数量输入 `0` 至 `6` 的选择结果也一致，包含原有数量截断行为。输出 XLSX 的所有 ZIP 成员内容一致，仅规范化 `docProps/core.xml` 的创建和修改时间；容器条目时间戳不参与比较。

240 组固定随机种子的受控小规模输入覆盖四个优化分支，共完成 960 次单客方案、240 次每厨具方案和 96 次默认候选池对照。覆盖条件包括得分门槛、订单量、空或重复偏好、喜爱与厌恶重叠、覆盖与流行链、禁忌名称／标签、重复加料、等价去重开关、缺失／负数／非有限供给、重复料理名及含键分隔符的食材名。全部对照一致。默认候选生成函数未启用内部界限时仍返回原候选池。

另完成四个入口各 58 位顾客、共 232 份完整候选结果对照，以及 14 个明确排序与边界用例，全部一致。差分对象包括候选的基础与追加食材、多重集计数、最终标签、得分、件数及内部比较键。相同食材件数的候选仍执行原供给与确定性决胜比较；CLI 参数声明、交互提示和输出写入函数保持原实现。该证据验证所列条件下的优化等价性，候选生成原有的启发筛选边界仍然存在。

## 当前网页差分验证

对 v1.0.0 与当前 Worker 内核完成 198 组差分对照，逐项比较完整结果行、行序及各阶段候选数量：

- 六个布尔选项的全部 64 种组合。
- 58 位稀客与全部 164 条料理记录，使用从真实数据中选取的 12 种食材。
- 64 组扩展输入，包含超过 80 个标签及中文排序下等价的不同 Unicode 字符串。
- 必含／排除标签、双向流行触发链、Top-N 边界、空输入，以及选定料理使用全部 61 种网页食材的条件。

全部结果及顺序一致。另完成 108 组位集边界对照，检查第 31、63 位等符号位和跨 32 位字的必含／排除判断，结果一致。27 组重复搜索与筛选对照一致，搜索缓存未向导出对象添加字段。停止流程检查确认终止全部当前 Worker、使已排队消息失效并恢复按钮状态。

内部浏览器以完整工作簿核验加载、真实头像、候选计算与搜索。像素样式在桌面和 390 像素视口下完成检查；窄屏页面无整体横向溢出，八列表格通过独立滚动保留全部字段。样式检查中，莉格露启用等价去重与 TDQ 推荐后得到 251 条候选，搜索“饭团”得到 9 条；该案例用于确认界面流程，不作为耗时基准。

合并样式与优化逻辑后，再以博丽灵梦、最低分 3、无流行、仅开启子集过滤与等价去重进行检查：完整结果为 4,372 行，搜索“饭团”后为 59 行，导出的 XLSX 为 `结果` 工作表、60 行（含表头）及原有八列。点击停止后可立即重新计算；四项主要选项全部开启后得到 145 行，CSV 导出包含 146 行（含表头）及相同八列。浏览器控制台未观察到错误。

## 性能测量口径

Python 测量使用 Windows 11、Python 3.12.14，在同一工作站串行交替运行基准版与当前 `nCookware`，各三次。条件为完整工作簿、58 位顾客、最低分 3、每客日订单量 5、无流行喜爱、流行厌恶「水产」和五种厨具。计时从进程启动至正常退出，包含模块加载、读取工作簿、候选搜索、共同厨具选择和 XLSX 写出。六次运行均正常结束，输出工作簿在排除前述时间元数据后完全一致。

| 实现 | 完整 CLI 耗时中位数 | 三次范围 |
| --- | ---: | ---: |
| v1.0.0 | 106.249 秒 | 105.883–121.057 秒 |
| 当前实现 | 4.147 秒 | 3.976–4.591 秒 |

中位数之比为 25.62。Python 程序仍为串行 CPU 执行，加速来自搜索界限，未增加并行进程。

网页测量在 Windows、Node.js 24.22.1 的独立 VM 环境中运行 Worker 内核。输入为完整工作簿解析出的 61 种食材、164 条料理和博丽灵梦；最低分 3，流行、必含与排除标签为空，子集过滤、高级过滤、等价去重及 TDQ 推荐开启，两项“考虑得分”关闭，Top-N 为 3。三组配对运行均输出相同的 145 行结果。内核耗时中位数由 50.42 秒降至 19.52 秒，约为基准版的 2.58 倍速度。

上述网页计时不包含工作簿加载、Worker 创建与消息传递、DOM 渲染和浏览器调度；端到端浏览器耗时需单独测量。两组测量使用日常工作站，后台编辑器和浏览器活动可能影响耗时。结果限定于所列环境与数据，不代表跨设备性能。算法依据与测量摘要见 [README 求解算法](../README.md#zh-algorithms)。

## 适用范围与未覆盖项

- v1.0.0 的既有空流行、三种厨具运行在 60 秒时终止，未获得该情境的完整输出；历史菜单复现对应水产流行厌恶、五种厨具的特定情境。

- 跨浏览器兼容性、跨设备性能及不同数据规模下的耗时尚未系统测量。
- 现有验证未包含完整经营收益实验、共享库存约束验证或全局最优性证明。

各项结论限于对应版本及所列运行条件。算法候选范围与数据不确定性分别见[设计说明](design.md)和[数据来源说明](data-provenance.md)。
